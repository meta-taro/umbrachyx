# 002 木の方式を選ぶ

## 目的
構想では、メモリ上の状態と履歴の置き場は同じ Merkle 木。差分のコストは「変更の量」に比例する必要がある。
方式によって、この性質と読み書きの速さが変わる。

## 作業
- 候補を 2 つ以上、同じ合成データで比べる（例: prolly tree / 永続 B 木 / HAMT）
- 既存の実装を先に調べる（Dolt の prolly tree、Irmin。Rust の crate があれば使えるかも見る）
- 測るもの: 読み書きの p99、100 万件のうち 10 件を変えたときの差分の時間、枝を作る時間、メモリ量

## 完了条件
- [ ] 差分の時間が「変更の件数」に比例し「全体の件数」に比例しないことを、ベンチの表（全体 10 万 / 100 万 / 1,000 万）で示す
- [ ] 選んだ方式と、選ばなかった方式を捨てた理由を decisions に書く
