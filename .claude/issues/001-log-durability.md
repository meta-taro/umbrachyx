# 001 追記ログの耐久性

## 目的
構想の要は「ログに書けたら確定」。ここが崩れると、木も履歴も全部崩れる（D5）。
最初に実測して、書き込みの確定をどこで返すかを決める。

## 作業
- 追記専用ログの最小実装（1 件 = 値 + who / why / approved-by）
- fsync の方式を Windows と macOS で実測する（macOS は `fsync` だけではディスクまで届かない。`F_FULLFSYNC` を比べる）
- 書いている最中にプロセスを強制終了し、再起動後にログを読み直す試験
- 末尾が半端に書かれた記録を検出して切り捨てる（チェックサム）

## 完了条件
- [ ] 強制終了の試験を 1,000 回回し、確定を返した書き込みの消失が 0 件（Windows・macOS の両方で）
- [ ] 1 件あたりの確定までの時間（p50 / p99）を、fsync の方式ごとに表にして decisions に書く
