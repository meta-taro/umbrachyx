# ベンチマークと堅牢性試験のルール

速さと壊れにくさは、実績の代わりに数字で示す。数字は、誰でも同じ手順で流し直せる形で公開する。

## 1. いつ流すか

| いつ | どこで | 何を | 公開するか |
|---|---|---|---|
| push のたび | GitHub の CI（自動） | `bench/` の3本と、堅牢性の試験すべて | artifact に残すだけ。README には載せない |
| 速さ・耐久性に触れる変更の commit 前 | 手元 | 変更に関係する測定 | 載せるなら、同じ commit で README も直す |
| **バージョンアップのたび（必須）** | 固定の測定機（§2） | 3本 × 3回と、堅牢性の試験すべて | `bench/results/` と README の表を更新する |

- CI 機は他と共有しているので数字がぶれる。前の run と比べて遅くなっていないかを見るためだけに使い、README の表にはしない。
- バージョンアップの測定を飛ばしたまま、リリースしない。

## 2. 固定の測定機

バージョン間で比べられるように、条件を毎回そろえる。

| 項目 | 値 |
|---|---|
| 機種 | AWS EC2 `m6id.xlarge`（4 vCPU・16 GiB、ローカル NVMe 237 GB） |
| リージョン | `ap-northeast-1`（東京） |
| OS | Ubuntu 24.04 |
| ログを置く場所 | ローカル NVMe（ネットワークディスクにしない） |
| 支払い方法 | オンデマンド（スポットは途中で止められ、測り直しになるため使わない） |

- **条件を変えるときは**、理由を `docs/comparison.md` に書き、新旧の両方の機械で同じ commit を1回ずつ測って、つなぎ目を残す。
- 毎回 Valkey も同じ機械で測り直す。倍率は、同じ機械で測った値同士でしか出さない。
- ほかの機械（ノート PC、Xserver VPS など）の数字は、参考の列として README に並べてよい。そのときは機械・プラン・CPU が専有か共有か・ディスクの種類を書く。

## 3. 流すもの

```sh
bench/umbrachyx.sh
bench/valkey.sh
bench/connections.sh          # 先に ulimit -n 65536
cargo test -p umbrachyx --release --test server_crash -- --ignored --nocapture
cargo test -p umbrachyx --test crash -- --ignored --nocapture
cargo test -p umbrachyx --lib --release ten_thousand_seeds -- --ignored --nocapture
```

- ベンチマークは3回流す。README には中央値を書くか、幅で書く。
- 堅牢性の試験が1つでも落ちたら、リリースしない。落ちた試験を消したり、回数を減らしたりして通さない。

## 4. 公開の仕方

- 生の出力は `bench/results/<日付>-<機械>/` に置き、そのまま残す。CSV を手で直さない。
- 同じフォルダの `README.md` に次を書く：機械・OS・版（Rust、Valkey）・測った commit・流したコマンド。
- README の「Numbers so far」と `docs/comparison.md` の表は、結果を置いたのと**同じ commit で**直す。
- **負けた行も同じ表に載せる。**勝った行だけを選んで載せない。
- 測っていない数字は書かない。機械によって倍率が大きく変わるものは、両方を並べる（例：書き込み中の GET は、ノート PC で約650倍、Linux の CI 機で約20〜28倍）。

## 5. 費用と後片付け

### 費用の目安（2026-11-04 時点。使う前に公式の料金表で確かめる）

| 項目 | 目安 |
|---|---|
| `m6id.xlarge` 東京・オンデマンド | 約 $0.31/時間（バージニア北部 $0.237 に、東京の割増を掛けた見積もり） |
| 起動ディスク（gp3 30 GB）・公開 IPv4 | 1時間あたり約 $0.01 |
| 1回の測定（組み立て・3回の測定・堅牢性の試験・回収で、約1.5時間） | **約 $0.5（1ドル150円で約75円）** |
| バージョンアップが月4回の場合 | 月に約 $2（約300円） |
| GitHub の CI（public リポ） | 無料 |
| Xserver VPS（別の目的で契約するものを1回借りる） | 増える費用なし（8 GB プランは月3,201円からという記事がある） |

### 消し忘れがいちばん高い

- `m6id.xlarge` を消し忘れると、**1か月で約 $230（約3.4万円）**かかる。1回の測定の約450倍。
- 測定が終わったら、**結果を回収してから VM を「終了（terminate）」する。**「停止」だけにしない（起動ディスクの課金が残る）。
- 消したあと、EC2 の一覧に実行中のものが無いことを確かめる。
- AWS Budgets で、月 $10 を超えたら通知が来るようにしておく（設定は人が行う）。

## 6. 権限と安全

- AWS のアカウント・鍵・権限の設定、SSH の鍵は、**人が作って入れる。**AI は作らない・置かない・貼らない。
- 自動にするときは、長く使える鍵を GitHub に置かずに済む方式（OIDC）を使う。
- umbrachyx も Valkey も `127.0.0.1` だけで待ち受ける。測定用のポートを外へ開けない。外から入れるのは SSH だけにする。
- データは合成データだけを使う。実在のサービスのデータは入れない。
